# Review Gates

## 1. 文档目标

定义协调 Agent 在回收实施 Agent 结果时的统一审查门槛。

## 2. 通用审查门槛

每个工作包回收时，至少检查：

- 是否符合 `constitution`
- 是否符合对应 spec
- 是否修改了未授权模块
- 是否补充了最小验证
- 是否留下未声明的技术债

## 3. 结构性红线

出现以下任一情况，不进入下一阶段：

- 把状态只放内存
- 跳过 `baseline_post_id`
- 跳过 `delivery_events`
- 轮询模块直接调用飞书
- API 返回敏感 webhook 信息
- 未声明地把 SQLite 路线改成其他数据库

## 4. Batch A 审查点

- 工程结构是否与 spec 一致
- 配置是否集中管理
- 数据表是否完整
- 索引和唯一约束是否存在

## 5. Batch B 审查点

- 是否正确处理首次接入基线
- 是否正确过滤 reply / repost
- 是否只在成功时推进 `last_seen_post_id`
- 是否避免重复创建事件

## 6. Batch C 审查点

- 是否严格依赖 `delivery_events` 做幂等
- 重试是否符合 1/5/15 分钟策略
- `sending` 僵尸任务是否可恢复
- `/ready` 是否检查真实依赖

## 7. 交接格式

实施 Agent 回传结果时，建议统一格式：

1. 本次完成内容
2. 修改文件
3. 验证结果
4. 风险与遗留
5. 是否请求协调 Agent 决策
