# V1.2 Admin History Usability - Intake

## Feature ID

`v1-2-002-admin-history-usability`

## Problem

The local admin page is usable, but history tables are still hard to scan:

- Time fields use raw ISO-like strings instead of a readable local format.
- Poll run error details are compressed into one `error_summary` column.
- Poll run and delivery event lists are fixed-size recent lists without pagination.

## Target User

The local operator using `http://127.0.0.1:3000/admin` to inspect polling and delivery health.

## Desired Outcome

Improve admin history readability:

- Show relevant timestamps as `2026/5/18 10:45:32`.
- Remove the poll-run error summary column from the table.
- Add an operation column with a "查看错误" button for failed poll runs.
- Show a modal with account-level error details.
- Add pagination to recent poll runs and recent delivery events.

## Non-Goals

- No frontend framework.
- No authentication changes.
- No polling or delivery state-machine changes.
- No Feishu message format changes.
- No new database table unless review determines existing data is insufficient.

## Affected Modules

- `src/modules/api/controllers/admin-controller.ts`
- `src/modules/api/routes/admin-routes.ts`
- `src/modules/storage/poll-run-repository.ts`
- `src/modules/storage/delivery-event-repository.ts`
- `README.md`

## Initial Technical Finding

Current `poll_runs.error_summary` stores failed account details as text generated by the polling orchestrator.

V1.2 can use this field for the modal without adding a migration. This is acceptable for local V1.2, but it is not a perfect structured audit trail.

## Open Questions

- None blocking. Use browser local timezone for display formatting.
