# Spec

## 背景

监听源页面的行信息以原始 URL 作为标题、徽章被挤压换行，且没有批量清理入口；绑定端来源选择显示原始链接；另外需要限制每个用户只能绑定一个微信。

## 目标

1. 监听源页面：一键删除全部监听源（含级联清理消息与投递记录，二次确认）。
2. 监听源页面 UI：来源使用中文友好名称（arXiv cs.AI、Hacker News 首页、Reddit r/…、OpenAI 新闻 等），原始地址降为次要行；徽章不换行。
3. 每个用户最多绑定一个微信号：后端拒绝第二个绑定（409），前端按钮禁用并提示。
4. 绑定端来源选择：按组展示（AI 官方源 / 论文与榜单 / 开发者 / 资讯与社区 / X 账号 / 其他），使用中文友好名称。

## 非目标

- 不改变投递通道（飞书等）的展示。
- 不新增来源类型；未知来源仍回退到域名 + 路径。

## 边界条件

- 一键删除删除全部监听源（含被过滤/禁用项），不可恢复；删除后页码回退到第 1 页。
- 友好名称是展示层映射，不改数据库；未知 RSS 显示 hostname+path。
- 扫码时会话只认领一个无主账号，保证单绑定语义。

## 验收标准

- [ ] 监听源页可一键删除全部源，确认框显示数量，删除后列表清空
- [ ] 来源标题为中文友好名，徽章不裁剪，原始地址为次要行
- [ ] 第二次绑定微信返回 409，前端绑定按钮禁用并显示提示
- [ ] 绑定端按组展示中文来源名
- [ ] smoke/typecheck/build 通过
