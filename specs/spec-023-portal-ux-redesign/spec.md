# Spec

## 背景

用户绑定端（`/portal`）上线后收到三类体验问题反馈：

1. 「夜间静默」「接收源」的开关按钮在**关闭态**底色为 `#667e8b`（偏深的灰蓝），与开启态 `var(--accent)`（靛蓝）明度接近，用户无法一眼分辨开/关。
2. 微信推送页绑定后呈现三张卡片（左列「微信连接」卡，右列「夜间静默」「接收源」两张偏好卡），布局割裂、视觉层级混乱。
3. 消息页为单列列表 + 「加载更多」，PC 宽屏下信息密度低，没有分页能力。

> 原第 4 项（源选择流程与「空选择 = 不推送」语义）经用户复核后**撤销**：现状（取消最后一个源自动回到「全部接收」并收起面板；空选择 = 全部推送）被认为合理，本次不做任何改动，后端无涉及。

## 目标

1. 开关组件具备明确的**开/关视觉区分**。
2. 微信推送页卡片结构重排：右栏偏好合并为单张「推送设置」卡，层级清晰。
3. 消息页改为 3 列网格 + 数字分页。

## 非目标

- **不改**接收源的交互流程与「全部/自定义」语义（现状保持）
- 不改投递通道、轮询调度等后端逻辑（本次纯前端）
- 不做消息页搜索能力变更
- 不做管理端（admin）样式调整
- 不引入新的 UI 组件库

## 当前行为

- 开关：`.me-switch` 关闭态 `background: #667e8b`，开启态 `var(--accent)`；「接收源」开关 `on: !sourcesAll`（开=自定义）
- 布局：`.me-wechat-layout.is-bound` 两列（1fr / 1.15fr），右列 `.me-preferences` 垂直堆两张卡
- 消息页：`.me-post-list` 单列 flex，`pageSize=20`，尾部「加载更多」按钮

## 目标行为

### A. 开关视觉

- 「夜间静默」开关：关闭态中性浅灰底（`#cbd5e1` 级别）+ 白色圆钮，hover 微深；开启态 `var(--accent)` 底
- 「接收源」行改用**分段选择器**（segmented control）替代开关：`全部接收 | 自定义接收` 两枚互斥 pill，选中态用 accent
- 注意：分段选择器只是**视觉控件替换**，模式语义与保存逻辑完全不变（自定义面板 `v-if` 跟随自定义态；取消最后一个源仍回到全部接收并收起面板）

### B. 微信推送页布局（用户已确认：合并为单张设置卡）

- 绑定后仍两栏：左栏「微信连接」卡（绑定账号 / 会话状态 / 解绑 / 推送额度）
- 右栏合并为**一张「推送设置」卡**，内部两个分组（小节标题 + 图标）：
  - ① 夜间静默：开关 + 时间范围
  - ② 接收源：分段选择器 + 分组 chips
- 移动端（≤920px）单栏堆叠

### C. 消息页（用户已确认：3 列 + 18 条 + 数字分页）

- PC（≥980px）：帖子一行 **3 列**网格（卡片等高对齐，长文折叠规则保留）；≤980px 2 列；移动端 1 列
- 分页替代「加载更多」：页码控件 `« ‹ 1 2 … n ›`（当前页高亮，多页折叠省略号），保留「共 N 条」
- `pageSize` 20 → **18**（3 列 × 6 行整除）；翻页/搜索时重置长文展开状态
- 移动端同样使用数字分页（移除「加载更多」）

## 功能需求

1. 本次为**纯前端**改动：`PortalPage.vue` + `public.css`（必要时 `styles.css`）+ `admin-api.ts`（如需类型调整）+ `i18n.ts`
2. 所有新增文案（分段选择器标签、分页 aria 等）中英文 i18n 同步
3. 保存行为维持自动保存 + 「已保存」轻提示

## 边界条件

- 自定义模式下源列表为空（管理员未建源）→ chips 区显示空态（现状保留）
- 搜索与分页组合：搜索后回到第 1 页；页码越界时后端返回空页，前端显示空态
- 长文展开状态在翻页后不跨页保留

## 技术约束

- 不新增依赖；不改 Prisma schema；不改后端接口
- 视觉跟随现有 portal 设计语言（圆角卡片、`--accent` 体系）

## 兼容性要求

- 后端接口零改动：`updateMyWechatSources` 仍传 `sourceIds` 数组（空=全部），语义不变
- 管理端不受影响

## 验收标准

- [ ] 「夜间静默」开关关闭/开启态肉眼可辨；「接收源」为「全部接收 | 自定义接收」分段选择器
- [ ] 源选择流程与现状完全一致（取消最后一个源 → 回到全部接收并收起面板）
- [ ] 绑定后右栏为单张「推送设置」卡（两个分组），移动端正常堆叠
- [ ] PC 消息页一行 3 卡；分页控件翻页正确、pageSize=18；移动端单列 + 同款分页；「加载更多」移除
- [ ] 中英文 i18n 完整
- [ ] `npm run typecheck` + `npm run smoke:e2e` 通过（纯前端改动，smoke 应全绿无新增）
