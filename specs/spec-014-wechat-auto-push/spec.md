# Spec

## 背景

多账号微信桥上线后，投递需要手工在「投递通道」里逐个配置（账号+目标），与「微信」页签的账号管理重复。用户期望：**添加微信号后默认即接收推送**，并可按账号单独关闭推送。

## 目标

1. 自动建通道：检测到已绑定微信号时自动为每个账号创建/维护一条投递通道（`targetKey = wechat:<accountId>`，目标 = 该账号的 userId，默认启用）。
2. 账号级开关：微信页签「已绑定微信号」列表提供「接收推送」开关（PATCH `/admin/api/wechat/accounts/:id/push`）；同步逻辑不得覆盖用户手动关闭的状态。
3. 自动清理：账号删除时同步删除其通道；历史遗留/非规范的微信通道（同账号但 targetKey 非规范）自动清理，避免重复推送。
4. 移除冲突 UI：删除微信页签的「消息投递到微信」手动配置区块；「投递通道」类型下拉不再提供微信；列表接口支持 `excludeChannelType`，微信通道不出现在投递通道列表与统计中。

## 非目标

- 不做按账号的消息模板/规则隔离（规则仍可对全部通道生效）。
- 不改变官方限制（每微信号各自扫码、单实例绑定）。

## 边界条件

- 桥未安装/未运行：不执行同步，也不报错。
- 同步幂等：重复执行不产生重复通道；`enabled` 状态以用户操作为准。
- 账号尚无 userId（异常数据）：通道仍创建，仅不回填目标（发送时桥端回落最近会话）。

## 技术约束

- 复用既有渠道类型与发送器，不新增迁移（config_json 存储 accountId/target）。

## 验收标准

- [ ] 新绑定微信号 → 自动出现启用状态的推送通道
- [ ] 关闭某账号推送 → 同步后保持关闭；重新开启正常
- [ ] 删除账号/删除遗留重复通道 → 对应通道同步移除
- [ ] 投递通道列表与统计不再包含微信通道；微信页签无手动投递区块
- [ ] smoke 覆盖自动创建/开关保持/删除同步；README/roadmap 更新
