# Spec

## 背景

当前管理台仅限本机访问、无账号体系。需要增加登录机制，并区分两类界面：

- **管理端**：现有管理台，仅管理员可用；**所有访问（含本机）都需要登录**（用户选择）。
- **登录端**：普通用户登录后**只能绑定/解绑自己的微信**（接收推送），看不到消息与配置。
- 账号不开放注册：仅管理员在管理端创建用户；首个管理员由 `.env` 种子创建。

## 目标

1. **账号与会话**
   - `users` 表：用户名唯一、密码（scrypt 加盐哈希）、角色 `admin|user`。
   - `user_sessions` 表：会话 token（仅存哈希）、过期时间（30 天）；HttpOnly + SameSite=Lax Cookie。
   - 启动时若没有任何用户：优先用 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 创建管理员；缺失则生成随机密码并打日志提示。
2. **访问控制**
   - `/admin/*`（页面与 API）：需要管理员会话；未登录 401（页面重定向到 `/login`），普通用户 403。
   - `/user/api/*`：需要任意登录会话；越权操作 403。
   - `/auth/login|logout|me`：公开。
   - 取消"仅本机可访问管理页"限制（改为登录控制）。
3. **管理端用户管理**
   - 配置页新增「用户」页签：列表、新增（用户名/密码/角色）、删除、重置密码；不允许删除最后一个管理员。
   - 微信页签显示绑定归属（用户名）。
4. **登录端（绑定微信）**
   - `/login`：用户名 + 密码登录；登录后管理员进入管理台、普通用户进入 `/portal`。
   - `/portal`：显示绑定的微信号列表；扫码绑定（复用桥的登录流程）；解绑自己的账号（二次确认）。
   - 绑定归属：`delivery_targets.owner_user_id`；扫码发起时记录发起人，账号完成绑定时归属该用户。
   - 同一时间只允许一个扫码流程；进行中再次发起返回 409。

## 非目标

- 不开放注册、不做第三方登录/OAuth。
- 不做细粒度权限（普通用户仅绑定微信）。
- 不做多租户隔离（消息与源对普通用户不可见）。

## 边界条件

- 登录失败统一 401「用户名或密码错误」，连续失败做简单限速（每 IP 每分钟 10 次）。
- 会话过期/登出后立即失效；删除用户同时删除其会话，其微信绑定保留但归属清空（管理员可再分配/解绑）。
- 无用户且无 env 种子：生成随机管理员密码并写入日志（仅首次）。

## 技术约束

- 不新增依赖（scrypt/HMAC 用 `node:crypto`；Cookie 手动解析与序列化）。
- 迁移仅新增表与列。

## 验收标准

- [ ] 未登录访问 `/admin/api/*` 401、管理页跳转 `/login`
- [ ] 管理员登录后可用管理台；普通用户访问管理台被拒
- [ ] 管理员可创建/删除用户、重置密码；不能删除最后一个管理员
- [ ] 普通用户登录后仅能绑定/解绑自己的微信，越权 403
- [ ] smoke 覆盖鉴权、越权、用户管理、绑定归属；README/roadmap 更新
