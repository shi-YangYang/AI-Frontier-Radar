# Spec

## 背景

普通用户在 `/portal` 绑定微信后，会收到**全部监听源**的推送。用户希望能按源选择：只接收自己关心的源。

## 目标

1. 绑定端（`/portal`）每个微信绑定可配置「接收的消息源」：
   - 默认「全部源」（保持现状）；
   - 可切换为「自选源」，勾选任意数量的监听源；
   - 提交后立即生效（后续轮询按此过滤）。
2. 后端过滤：轮询创建投递事件时，若目标配置了 `sourceIds` 且不含消息来源的监听源 id，则不创建该目标的投递事件。
3. 管理端微信列表返回 `sourceIds`（只读展示用，管理 UI 不改）。

## 非目标

- 不改变全局关键词订阅规则的行为（两者叠加：先过关键词规则，再过源过滤）。
- 不做按源分渠道路由（仍由管理端分渠道规则负责）。
- 不通知已发事件的历史撤回。

## 边界条件

- `sourceIds` 为空/缺省 = 全部源。
- 保存时过滤掉不存在的源 id 与空字符串并去重；同一消息来自多个源时以首次入库的源为准。
- 源被删除后，其 id 残留在过滤列表中被忽略（不影响其他源）。

## 技术约束

- `delivery_targets.config_json` 增加可选 `sourceIds`（无迁移）。
- 新接口：`PUT /user/api/wechat/accounts/:accountId/sources`，仅绑定所有者可操作。

## 验收标准

- [ ] 绑定端可按源多选保存，刷新后保持
- [ ] 未选中的源推送不会创建该目标的投递事件，选中的正常创建
- [ ] 越权修改他人绑定返回 404
- [ ] smoke 覆盖接口与投递过滤；typecheck/build 通过

## 待确认问题

无。
