# Spec

## 背景

订阅源体系经产品调研确认三类问题：内容结构缺陷（服务器 22 个源中 X=0、YouTube=0，产品使命"监听 X 账号"缺席）；用户端分组按平台/域名启发式切分（同一主体拆散、无层级）；选择 UX 无承载结构（40+ chips 平铺、无推荐中间态）。

**用户决策（已确认）**：A+B 混合——以「主题包」为用户端选择单位（A）+ 用户端分组/标识重构（B）+ 管理员可管理主题包；旧「监听组合」预设 API 连带删除；停用包不清用户选择；包模式有效源集为空时不推送。

## 目标

1. 引入**主题包（Source Pack）**：命名+描述+源成员的管理单元，投递过滤按包解析。
2. **管理员管理主题包**：创建/编辑/删除、维护成员（多选）、排序、启停；删除提示影响并清理用户选择，停用保留选择。
3. **用户端三分段选择**：`全部接收 | 按主题包 | 自定义`；按包选自动纳入包内后续新增源；自定义保留逐源细选并按所属包分组展示。
4. chip 与包卡片带**平台小标**（X / YouTube / 博客 / GitHub / 榜单 / 其他）与生效源数提示，解决"如何区分、现在在收什么"。

## 非目标

- 不改 X/YouTube 抓取实现与代理边界（内容补充是管理员运营动作）
- 包成员变化不主动通知用户（管理端提示影响，用户端徽标反映状态）
- 不做管理端微信配置页改动（review 后如需同步另行处理）
- 不引入 UI 组件库

## 当前行为

- 预设：`src/config/source-groups.ts` 的 `ai-news` 组合，AccountsPage「监听组合」面板一键批量添加（`GET /admin/api/source-groups`、`POST /admin/api/source-groups/:id/apply`）
- 用户端：`source-labels.ts` 启发式 6 组；Portal「接收源」二分段 + 平铺 chips
- 选择存储：`delivery_targets.config.sourceIds`（不存在/空 = 全部接收）
- 投递过滤：`polling-account-service.ts acceptsSource()` 按 `config.sourceIds` 判断

## 目标行为

### 数据模型

- `source_packs`：`id, name(唯一), description, sort_order, enabled, created_at, updated_at`
- `source_pack_items`：`id, pack_id(级联), watch_account_id(级联)`，`(pack_id, watch_account_id)` 唯一；同一源可属多包
- `delivery_targets.config` 新增 `packIds?: string[]`；模式判定：`packIds` 非空 → 按包；否则 `sourceIds` 非空 → 自定义；皆空 → 全部

### 种子迁移（幂等）

- 首启 ensure 现有 `ai-news` 预设源存在（复用 `applySourceGroup` 逻辑）→ 创建首个包「AI 消息」并挂载全部命中源；已存在同名包则跳过
- **旧「监听组合」API 连带删除**（用户已确认）：管理端路由/控制器函数、`admin-api.ts` 封装、AccountsPage 面板、smoke 相关断言；`SOURCE_GROUPS` 配置保留仅作种子数据

### 管理端（AccountsPage「主题包」面板，替代监听组合面板）

- 包列表：名称、描述、源数、启停开关、排序（上移/下移）
- 新建/编辑：名称（必填唯一）、描述、从现有源多选成员（带搜索/分组浏览）
- 删除：二次确认显示「该包被 N 个用户选择，删除后其选择被清理（仅剩其它包的用户继续按包接收；全部包被删的用户回退全部接收）」；删除级联清理用户 `packIds` 中该包 id 并落库
- 停用：**保留用户 `packIds`**，投递端忽略停用包；重新启用自动恢复生效；管理端停用提示"用户选择将保留，期间其将收不到该包内容"
- 包卡片（用户端）：空包（无成员）置灰 + 「暂无内容」；成员被停用的包显示「已停用」徽标

### 用户端（Portal「推送设置」卡 ② 接收源）

- 分段选择器三段：`全部接收 | 按主题包 | 自定义`（UI 互斥，数据层 union 兼容）
- 段说明文案：按主题包段显示"包由管理员维护，包内新增内容将自动纳入推送"
- **每段下方显示当前生效源数**（me-inline-state）：全部 = N；按包 = 所选包 union 后源数；自定义 = 已选源数
- 按主题包段：包卡片多选（名称/描述/源数/平台聚合小标/停用徽标/空包置灰），选中即自动保存
- 自定义段：保留现有逐源 chips 流程与全部语义（取消最后一个源 → 回到全部接收并收起面板）；chips 按所属包分组（包名小节头 + 「未分组」兜底），chip 带平台小标
- 存量用户（`sourceIds` 非空、无 `packIds`）打开页面落在「自定义」段，无感迁移

### 投递过滤语义

- 有效源集解析（每次投递周期每 target 一次，非逐条消息）：
  - `packIds` 存在：union(启用的包的成员源 id)；**解析后为空 → 不推送**（包全停用/全悬空场景，用户端显示状态）
  - 否则 `sourceIds` 存在：非空 → 按列表；空数组 → 全部（现状不变）
  - 均不存在 → 全部
- `packIds` 中未知 id（脏数据）忽略；包被删时已级联清理，无需运行时悬空处理（停用包 id 保留、解析时按 enabled=false 排除）

### API

- 管理端新增：`GET /admin/api/source-packs`、`POST /admin/api/source-packs`（名称/描述/成员）、`PUT /admin/api/source-packs/:id`（名称/描述/成员/排序/启停）、`DELETE /admin/api/source-packs/:id`（返回受影响用户数）
- 用户端：`GET /user/api/wechat/binding` 新增 `sourcePacks`（id/name/description/enabled/成员源列表）与账号 `packIds`；`PUT /user/api/wechat/:accountId/sources` 请求体 `{ mode: 'all'|'packs'|'custom', packs?, sourceIds? }`（兼容旧体：仅 `sourceIds` 数组 → 按自定义处理，空数组=全部，行为不变）

## 功能需求

1. 后端：Prisma schema+migration、storage 仓库（pack CRUD + 成员管理）、管理 API、用户 API、投递过滤、首启 seed
2. 前端管理端：主题包面板（列表/编辑器/删除确认含影响数/排序/启停）；监听组合面板与 API 封装移除
3. 前端用户端：三分段选择器 + 包卡片 + 生效源数 + chips 分组化 + 平台小标（`source-labels.ts` 新增平台徽标函数）
4. i18n 中英同步；README 记录机制与管理入口
5. smoke：改造旧断言 + 新增包用例（≥4 项）：建包挂源、用户选包后包内新源自动投递、停用包不投递且选择保留、删除包级联清理、包模式空集不推送、旧体兼容

## 边界条件

- 包名重复 → 409；空包可建（用户端置灰）
- 包成员源被删除 → 成员级联删除，包保留（源数-1）
- `packIds`/`sourceIds` 并存（数据层）→ union；脏 id 忽略
- 用户无微信绑定 → 源设置不可用（现状）
- 搜索/编辑成员时空结果态齐全

## 技术约束

- 投递路径性能：effective 集合按 target 缓存于单次轮询周期，禁止逐消息查库
- 迁移幂等可重入；seed 不重复建包/建源
- 不新增运行时依赖

## 兼容性要求

- 存量用户行为不变（自定义语义、空=全部）
- 管理端微信配置页本次不改（如发现展示缺失另行 spec）
- README 更新主题包机制说明
