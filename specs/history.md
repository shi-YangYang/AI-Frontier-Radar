# Spec History

> 已完成迭代的一句话归档。每条详细 `spec.md` / `plan.md` / `acceptance.md` 已按维护策略归档，可在引入本文件前的 Git 历史中查看；新 Spec 仍按 `specs/spec-XXX-short-name/` 创建，完成后将摘要补入本文件。

## 基础链路与来源（spec-001～010）

- **spec-001 轮询与投递解耦**：无投递目标时也照常轮询入库，首次接入只锚定最新帖子，不补发历史。
- **spec-002 RSS/Atom 多源**：接入 RSS/Atom 多源，增加稳定去重键与 http/https 抓取代理。
- **spec-003 来源预设**：支持按来源类型添加 YouTube、Reddit、arXiv、Hacker News 与 Product Hunt，并统一转换为标准 feed。
- **spec-004 管理台 UI 重构**：管理台收敛信息密度、补齐全站空态并完成 UI/UX 重构。
- **spec-005 本地 Feed**：输出本地 RSS 2.0 与 JSON Feed，并支持订阅规则过滤。
- **spec-006 Anthropic 新闻源**：接入 Anthropic 官方新闻页，用专用 HTML 解析替代 RSS。
- **spec-007 第二批官方源**：新增 AI2、Moonshot、Meta AI、xAI 官方源与 Mistral、Stability、HF Blog RSS 源。
- **spec-008 数据运维**：增加帖子导出、数据保留策略、数据库备份/恢复与运行日志页。
- **spec-009 基线与级联删除**：文章型源首轮仅锚定最新一条，删除监听源时级联清理消息与投递记录。
- **spec-010 多渠道投递**：新增企业微信、钉钉、Bark、通用 Webhook 通道与分渠道订阅规则。

## 微信与用户端（spec-011～020）

- **spec-011 微信桥**：以自建轻量桥复用腾讯 ClawBot 协议，实现个人微信推送。
- **spec-012 微信桥内置化**：主服务内置托管微信桥，设置页完成扫码登录、会话登记与测试发送。
- **spec-013 微信多账号**：支持多个微信号分别扫码绑定、按账号轮询会话并选择发送账号。
- **spec-014 微信自动推送**：绑定微信即默认接收推送，提供账号级开关并移除手动投递入口。
- **spec-016 登录与权限**：增加全站登录与角色权限，普通用户仅能管理自己的微信绑定。
- **spec-017 微信按源过滤**：绑定端可按监听源过滤推送，投递时按目标配置筛选。
- **spec-018 源运维与展示**：支持一键删除全部监听源、来源中文友好名与分组展示，且每个用户限绑一个微信。
- **spec-019 微信会话可靠性**：桥缓存并透传 `context_token`，会话失效快速失败不重试并在绑定端提示。
- **spec-020 用户端改版**：用户端改为消息浏览与微信配置双页签，增加额度进度与会话激活引导。

## 近期迭代（spec-021～031）

- **spec-021 管理端视觉重构**：管理端 15 个页面的布局、色彩、字阶、间距与组件视觉重构。
- **spec-022 钉钉扫码登录**：支持钉钉扫码登录、`unionId` 映射自动创建普通用户与可选 CorpId 专属登录。
- **spec-023 绑定端体验改版**：绑定端优化开关视觉、合并推送设置卡，并将消息页改为三列网格加数字分页。
- **spec-024 主题包**：引入主题包，管理员可建包/排序/启停，用户按包订阅并按包解析投递源集。
- **spec-025 扫码绑定中间态**：增加扫码中间态与等待 ClawBot 首条消息的引导，绑定后自动恢复。
- **spec-026 品牌与 Toast**：品牌统一为「消息雷达」，Toast 成功提示自动消失，微信卡片改为纵向堆叠。
- **spec-027 内置主题包**：内置论文、AI、机器人、脑机、融资五个主题包与针对性源，并增加包详情弹层。
- **spec-028 投递通道物理删除**：投递通道改为物理删除，进行中事件置 `dead`，历史投递记录保留。
- **spec-029 消息分类筛选**：用户端消息按平台分类筛选，服务端过滤并与搜索、分页联动。
- **spec-030 微信会话失效感知**：识别微信 `errcode=-14` 会话失效，清除本地凭证、发送快速失败并如实展示状态。
- **spec-031 轮询看门狗**：轮询单账号增加 60 秒看门狗，单源挂死不再阻塞整轮。
