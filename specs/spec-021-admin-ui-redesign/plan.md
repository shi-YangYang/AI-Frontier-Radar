# Plan

## 涉及模块

- `web/admin/src/App.vue`、`styles.css`、管理端页面和必要的公共组件/i18n。
- 浏览器截图与定向交互检查：临时用于诊断和视觉验收，交付后清理。
- 当前 Spec 与设计说明、最终独立验收记录。

## 修改顺序

1. 保留现有未提交工作，确认运行中的前端构建与基线对应；截图工具 Agent 完成 before 全页矩阵和 manifest。
2. 协调 Agent 联网研究并结合截图修订设计规范；实施 Agent 读取规范后统一修改高度耦合的管理端样式与模板。
3. 优先外壳/语义 tokens/控件，再总览与列表，再设置九个子页；将新增、推荐组合等辅助任务按需展开。
4. 通过前端类型检查后构建静态资源。重载页面，用同一工具获取 after；不重启后端、不触发业务任务。
5. 独立验收 Agent 检查所有页面截图及必要展示交互，结果写入 acceptance.md；具体失败由新的实施 Agent修复，再由新的验收 Agent检查。

## 数据流与接口

后端和 API 不变。只允许展示状态（展开、折叠、选择、弹层）和对应文案调整。

## 验证级别与计划

本次为 S2：多个管理端页面、公共外壳和组件相互影响。用户明确要求全量截图，因此运行完整管理端截图矩阵。

- 实施 Agent 负责一次 `npm run admin:typecheck` 和 `npm run admin:build`。
- 截图/验收覆盖双桌面尺寸，以及补充英文、窄屏、长内容、空态和受影响交互。
- 现有 `smoke:e2e` 主要为后端服务测试，本次没有后端修改，不默认执行；不运行全量 backend typecheck/build。
- 已通过检查仅在相关代码再次改变或发现具体失败后重跑。

## 风险与限制

共享 CSS 可能影响 login/portal、SelectControl 或 Teleport 弹层，需要作用域隔离及针对性回归。当前真实数据较少，真实空态和明确标记的浏览器 fixture 应分别记录。before 使用当前已运行构建，after记录新构建，不将旧文件冒认为本轮证据。

## 迁移与交付

没有数据迁移。保持 dev 分支与用户既有修改，按授权本地提交，不推送或部署。交付本地界面、设计依据与验收摘要；截图、画廊和一次性检查脚本完成验收后删除。

## 登录与用户端同步

- 保留管理员已完成的页面；基于原登录页与 PortalPage 两个标签重排品牌、表单、卡片和消息阅读区，沿用已有业务函数。
- 一个实施 Agent 负责耦合的模板和主题样式，必要时添加用户端专用 CSS，并通过路由主题覆盖 Teleport；不重构身份认证或 API。
- 截图 Agent 先采集 1280×800、390×844 三种页面的原状；实施完成后执行一次前端 typecheck/build，再定向获取 after、英文与必要 fixtures，抽查管理员主题隔离。
- 该同步涉及两页及主题集成，验证为 S2 前端子系统范围；不重复管理员全量矩阵，不运行后端检查。由新的独立验收 Agent 阅读增量 diff、截图和检查结果。
