# Spec — 管理员端布局与视觉重构

## 背景

管理员端已有未提交改版，但页面的信息层级、空间分配和配色仍不协调。继续以当前工作区为基线：先全量截图、根据官方设计资料研究，再实施结构与视觉改版并独立验收。允许调整管理端导航外壳、页面模板、组件和当前规格。

## 目标

- 覆盖全部 15 个管理员页面：6 个主页面与 9 个设置子页；另外截图登录页作为共享样式回归参考。
- 管理员能直接找到每页主要任务，列表优先展示数据，设置按任务分区。
- 建立统一且可读的色彩、字阶、间距、表格、表单、空态和交互状态。
- 将登录页与用户页的微信推送、消息列表同步到同一品牌视觉体系，保留用户端简洁的导航与阅读体验。
- 通过浏览器截图、运行诊断与前后对比完成视觉验收，保留覆盖范围、结果与限制，不能仅凭编译成功宣称完成。

## 非目标

- 不改变后端 API、采集、订阅、投递、权限和持久化业务规则。
- 不添加 UI 库、网络字体或运行时依赖，不升级工程工具。
- 不发送消息、不创建或删除真实业务数据、不部署或提交代码。

## 当前行为

- 监听源页推荐组合、添加表单、搜索同时展开，主列表位置偏低。
- 表单小字段过宽，重复页头和卡片头占空间，保存操作层次不清。
- 32px 控件、小字号、同权重白面板和多枚高饱和主按钮造成密度与重点失衡。
- 强制视口填充使少量数据产生巨大面板空白；嵌套滚动使长设置页难以完整检查。
- 原截图脚本每档实际 16 页，旧规格误写为 18 页；输出目录参数未生效，默认高度与规格不符。

## 目标行为

- 默认视觉方向为深蓝灰导航、浅中性画布、白色表面和青绿强调；此为项目设计选择，不冒充参考产品的官方色值。
- 页面标题、简短说明与最多一个主要动作构成页头；搜索/筛选与其作用的列表相邻。
- 管理主导航分组、当前项明确，设置子页和面包屑保持准确；沿用全部现有 URL。
- 监听源列表是默认主体；新增表单与来源组合渐进展开，原有能力仍可访问。
- 总览提供清晰指标与内容/状态分区，真实空态不能伪造数据或健康状态。
- 设置采用有边界的任务分区、顶部标签与合理字段宽度；状态摘要、编辑、列表分别组织。
- 表格支持长内容和必要的局部横向滚动，页面不能出现被裁切的关键动作。设置采用自然纵向滚动；运行日志仅表体独立纵向滚动，滚动条从表头下方开始，页头、工具栏与表头保持可见。
- 监听源的类型、主名称与显示名（如 OpenAI）同排展示；操作列删除按钮靠左并与列头对齐，长来源信息可合理换行。
- 登录页采用深蓝灰品牌区与浅色表单区、青绿主按钮；品牌区保留原有雷达同心圆与动态扫描，配合轻网格与青绿光晕，不能遮挡文案或表单。手机优先显示品牌与完整登录表单；系统开启减少动态效果时保留静态雷达。
- 用户页采用深蓝灰顶栏、浅色内容区与青绿选中状态。微信连接、推送额度、免打扰和来源选择有明确层级；消息页提供对齐的搜索工具与可读内容列表。未绑定、加载、失败与空消息状态如实展示。
- 登录和用户端的窄屏布局、英文文案、焦点、表单边界和弹窗风格一致。导航方式、默认标签、登录跳转和所有业务操作保持不变。

## 功能需求

1. **截图验证**：浏览器检查通过运行时环境变量提供登录凭据，代码与文档不固化密码；区分改版前后、页面路径和视口尺寸。
2. **截图矩阵**：1280×800、1600×1000 各覆盖 `/login`、`/`、`/accounts`、`/poll-runs`、`/posts`、`/delivery-events`、`/logs`、`/settings?tab=feishu|polling|xSource|rss|rules|wechat|data|users|runtime`。即每档 16 页，基础截图每阶段 32 张。
3. **完整内容**：保留正常布局截图；长页面和内部滚动内容补充分段或底部截图，不通过移除布局样式伪造全量覆盖。
4. **诊断**：验证时记录页面路径、视口、构建标识、加载错误和页面横向溢出；未登录探测的预期 401 单列。隐藏密码、Webhook 等敏感配置值，不隐藏视觉结构。
5. **组件**：统一 36px 主控件、中文正文约14px、页标题24px、分区标题16px；标准焦点轮廓、禁用状态、语义状态色、可读空态与分页。
6. **交互保留**：原搜索/筛选、分页、表单字段、详情、确认弹窗和设置切换保留；允许添加必要的本地展示状态及中英文文案。
7. **产物清理**：交付后删除截图、画廊、临时诊断和一次性检查脚本，包含 Spec 内重复截图；仓库保留业务实现、规格、设计依据及验收摘要。
8. **登录与用户端同步**：1280×800、390×844 覆盖登录页、用户微信页与消息页前后截图；补查登录校验、英文、长消息展开/搜索/加载更多、已绑定和未绑定展示。缺少数据的展示状态采用明确标记的浏览器 fixtures，不向真实账户保存设置或发起绑定。

## 边界条件

- 真实页面缺少数据时如实截空态；需要检查长文、密集数据、错误态时可使用明确标记的浏览器请求替身，只影响测试浏览器，不能写入真实数据库。
- 通用色彩可复用；管理员布局和登录/用户端布局仍应隔离。登录/用户端同步时抽查一个管理员页面的主题，不能改变已完成的后台布局。
- 桌面主验收外，检查窄屏可访问性、短视口与英文布局；不要求移动端完整重新设计。
- 页面刷新、轮询和测试截图不应触发主动发送、保存或破坏性操作。

## 技术约束

沿用 Vue 3、原生 CSS、现有组件与 Playwright；本地服务当前运行在 127.0.0.1:3000。改版后只构建前端静态产物即可更新页面，无需重启后端或执行数据库迁移。

## 兼容性要求

保留已有业务事件绑定、路由及服务接口；支持中英文；新展示逻辑满足键盘可用、明确标签和可见焦点。正文对比度以4.5:1为目标，状态不只依靠颜色。

## 验收标准

- [x] before/after 每阶段完成双视口 32 张基础截图及必要滚动补图，覆盖全部 15 个管理页。
- [x] 研究文档引用官方来源，并区分资料事实与本项目设计取舍。
- [x] 页头、工具栏、表格、设置和空态形成一致的视觉层级；不能只替换色值。
- [x] 不出现页面级横向溢出、关键操作裁切、文字不可读或异常长空白面板。
- [x] 添加源、来源组合、消息筛选/详情、表格选择/分页、设置子页等展示交互可用；验证不改变真实业务数据。
- [x] `npm run admin:typecheck` 与 `npm run admin:build` 通过。
- [x] 对路由切换、展开/收起、弹层和受影响共享组件进行浏览器检查；中英文、登录、portal 和窄屏没有直接回归。
- [x] 新的独立验收 Agent 检查 Spec、diff 和实际截图，出具 PASS/FAIL。
- [x] 登录、用户微信页、消息页完成桌面与窄屏视觉同步及前后截图；原业务行为保留。
- [x] 登录/用户端相关交互与状态通过针对性浏览器检查，前端类型检查与构建通过；新的独立验收通过。

## 待确认问题

无。沿用已选定的深蓝灰与青绿视觉方向。
