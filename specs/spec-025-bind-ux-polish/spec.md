# Spec

## 背景

用户扫码绑定微信后，二维码页面在扫码与手机确认之间没有任何 UI 反馈，且直到 ClawBot 会话激活前都不更新，用户以为绑定卡住。根因：协议要求收到一条来自用户的微信消息（记录 context_token）后才算会话就绪，而页面在这期间仍展示二维码且无中间态引导。

## 目标

1. 扫码中间态（`login.status='scanned'`）可感知：页面立即隐藏二维码，切换为「已扫码，请在手机上确认」状态卡。
2. 登录完成（账号已登记）但会话未激活时：绑定端展示明确引导卡「请在微信里给 ClawBot 发送一条消息」，成功后自动消失（沿用现有 3 秒轮询）。
3. 不改任何后端接口与协议（纯前端 + 不必要的上游打印过滤已移除）。

## 非目标

- 不改微信桥协议与登录流程本身
- 不做扫码状态的 WebSocket/SSE 实时推送（沿用 3s 轮询）
- 不做多用户会话隔离改动

## 当前行为

- `/auth` 登录绑定流程：`startMyWechatBind` → 桥生成二维码；`refreshBindStatus` 每 3 秒轮询 `getMyWechatBinding`
- 二维码期间 UI 无反馈：扫码成功（上游 status=scaned）不会更新页面；账号登记后 `me-status` 才开始展示会话状态
- 事件：仅成功（`sessionActive`）或失败时关闭二维码

## 目标行为

1. `PortalPage.vue`：
   - `next.login.status === 'scanned'` → 记录"已扫码"中间态，绑定区块切换为「已扫码，请在手机上确认」状态卡（隐藏二维码图）
   - `next.accounts.length > 0` 且 `!sessionActive` → 绑定区块切换为「等待你给 ClawBot 发送第一条消息」引导卡（含说明与图标，沿用现有文案 key）
   - `sessionActive === true` → 现有行为不变（成功提示 + 回正常态）
   - 失败路径（error / disabled / state 校验失败）行为不变
2. `login-worker.mjs` 无需改动（stdout 状态映射已够用）；若后续上游文本变化再另行处理
3. i18n：无新增 key（复用现有 `me.bind.*` 文案）；中英一致

## 边界条件

- 用户在「按主题包/自定义」等其它页签时绑定成功 → 仍在微信页签内切换状态，不影响其它页签
- 手机确认后立即取消绑定 → 按 failed 处理（现状）
- 会话激活后再次解绑 → 走现有解绑流程

## 技术约束

- 仅前端改动：`PortalPage.vue`（模板 + 少量状态分支）；不改 `login-worker.mjs`、不改后端
- 复用现有 `me-status` / `settings-form` 样式语言

## 兼容性要求

- `/auth` 与后端零改动；既有 smoke 全绿无新增

## 验收标准

- [ ] 扫码后 3 秒内页面出现「已扫码，请在手机上确认」状态卡（二维码隐藏）
- [ ] 账号登记后展示 ClawBot 引导卡，发送消息后页面自动恢复正常态
- [ ] 失败/超时路径与现状一致
- [ ] 中英文文案齐全
- [ ] `npm run typecheck` + `npm run smoke:e2e` 通过

## 待确认问题

- [x] 采用"状态卡"而非 toast 提示（与现有设计语言一致）
