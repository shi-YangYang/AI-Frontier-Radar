# Spec

## 背景

当前 `PollingAccountService.pollAccount` 在没有启用投递目标（飞书 Webhook）时直接抛错，导致：

- 没有任何账号会被真正抓取，帖子不入库；
- 本地帖子页（`/posts`）没有数据；
- 用户必须先配置 Webhook 系统才能工作。

抓取与投递应该解耦：抓取和入库是无条件能力，投递是可选下游。

## 目标

- 无启用投递目标时，轮询照常执行，帖子按现有基线/增量规则入库。
- 帖子内容在现有 `/posts` 页面可查看（含原文、作者、时间、原文链接）。
- 轮询统计（新帖数/待发送数）与是否配置投递目标无关，口径准确。

## 非目标

- 不新增独立看板页面（复用 `/posts`）。
- 不补发历史帖：之后配置 Webhook 只推送配置之后检测到的新帖。
- 不改变“首次接入只存最新 1 条基线”的行为。
- 不改变投递事件、重试、死信逻辑。

## 当前行为

- `deliveryTargets.length === 0` → `pollAccount` 抛 `No enabled delivery targets are configured.`，账号标记失败，帖子不入库。
- `newPostsDetected` 通过“新建投递事件数”统计，无目标时恒为 0。
- 有目标时：`x_posts_raw` upsert + 每个目标 `createIfAbsent` 投递事件。

## 目标行为

- 无目标：正常抓取、过滤（排除回复/转发）、基线/增量入库，不创建投递事件；账号轮询标记成功。
- 有目标：行为与现状一致（入库 + 创建事件）。
- 统计：`newPostsDetected` = 本轮实际新增入库的帖子数（不依赖事件）；`eventsCreated` = 新建投递事件数。

## 功能需求

1. 移除无投递目标时的早退抛错。
2. 帖子入库计数以「帖子是否新增」为准，避免重复轮询重复计数。
3. 轮询日志/记录中的“新帖 N 条 | 待发送 M 条”口径正确。
4. 确认 `/posts` 在无投递事件时正常展示帖子（含详情与原文链接）。

## 边界条件

- 无账号且无目标：轮询 run 成功，0 账号 0 帖。
- 有账号无目标：账号成功，基线/增量入库，0 事件。
- 重复/并发轮询同一帖子：不重复计数。
- 配置 Webhook 后：仅对之后的新帖创建并投递事件；此前存库帖不补发。

## 技术约束

- 不修改数据库 schema。
- 不新增外部依赖。
- 保持 `PollingAccountResult`、`PollingRunResult` 结构兼容。

## 兼容性要求

- 有投递目标的现有使用场景行为不变。
- `/poll-runs`、`/delivery-events`、飞书投递链路不受影响。

## 验收标准

- [ ] 无启用投递目标时，手动/定时轮询成功，账号 `lastPollStatus=success`，帖子按基线规则入库。
- [ ] 无目标时不产生 `delivery_events`。
- [ ] 有目标场景回归：新帖仍会创建事件并投递成功。
- [ ] 统计口径：`newPostsDetected` 按新增帖子计数，重复轮询不重复计数。
- [ ] `/posts` 展示入库帖子的原文、时间、原文链接。
- [ ] `npm run typecheck`、`npm run build`、`npm run smoke:e2e` 通过。

## 待确认问题

无。关键决策已与用户确认：不补发 / 复用 `/posts` / 保持首次基线 1 条。
